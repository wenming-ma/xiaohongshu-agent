## 目标

将当前 `workshop/image_post/topics.json` 的现有话题队列完整归档，然后将当前队列替换为 8 条围绕“求职面试有技巧”流量任务的专题话题，供 `workshop/image_post/run.py` 直接消费。

本次更新要贴近用户提供的活动参考图，优先覆盖以下 8 个细分方向：

1. 个人叙事 / 自我介绍埋钩子
2. 群面 / 压力面拆解
3. 面试官视角 / 判断维度 / 潜台词
4. 缺点包装 / 被质疑时的回答
5. 模拟面试
6. 反问环节
7. 面试复盘
8. offer call 谈薪

## 方案选择

### 方案 A：前置新增少量求职主题
保留现有主题，只把求职/面试相关主题插到最前面。

- 优点：改动小，保留原队列
- 缺点：当前任务主题不够聚焦，后续会混入非求职内容

### 方案 B：整文件替换为 8 条求职面试专题队列（采用）
完整归档旧文件后，用新的 8 条专题内容覆盖当前文件。

- 优点：和活动任务强绑定，执行顺序清晰，适合连续发布
- 缺点：需要通过历史归档保留原队列

### 方案 C：混合保留少量旧主题
保留少量高优先级旧主题，同时加入求职面试专题。

- 优点：兼顾旧内容
- 缺点：主题不够纯，和用户要求的“整文件替换”不一致

## 采用设计

采用方案 B。

### 文件变更

1. 新建目录（若不存在）：`workshop/image_post/history/`
2. 如果 `workshop/image_post/history/topics-2026-04-07.json` 已存在，则直接覆盖，因为本次归档目标是保存执行更新前的当前版本快照
3. 将当前 `workshop/image_post/topics.json` 原样复制到：
   - `workshop/image_post/history/topics-2026-04-07.json`
4. 用新的 8 条专题内容覆盖：
   - `workshop/image_post/topics.json`

### 新 topics.json 的结构要求

保持现有 JSON 数组结构，不修改字段名，不引入新字段。

每项继续使用：
- `topic`：小红书可直接发布的话题标题
- `audience`：目标受众，写具体人群
- `strategy`：说明该选题为什么有传播力/搜索价值/互动价值
- `format`：短标签形式，便于识别内容类型
- `priority`：以 `P0` / `P1` 标注优先级

## 计划写入的 8 条主题方向

最终写入 `workshop/image_post/topics.json` 的数组顺序必须严格按照下面 8 个方向依次排列，因为 `workshop/image_post/run.py` 会按顺序消费主题。

1. **自我介绍 / 个人叙事**
   - 方向：如何用关键词包装经历，在 1 分钟自我介绍里埋记忆点
2. **群面 / 压力面**
   - 方向：拆解面试环节背后的能力考察与心理博弈
3. **面试官视角**
   - 方向：从面试官判断逻辑解释候选人为什么被通过/挂掉
4. **缺点包装 / 被质疑应对**
   - 方向：如何回答“你的缺点是什么”以及如何承接追问
5. **模拟面试**
   - 方向：大厂面试官沉浸式模拟，提升内容代入感
6. **反问环节**
   - 方向：反问什么会加分，什么问题会暴露准备不足
7. **面试复盘**
   - 方向：亮眼案例、卡点问题、复盘优化路径
8. **offer call 谈薪**
   - 方向：谈薪话术、期望薪资表达、避免谈崩

## 选题风格约束

- 8 条内容必须严格限定在“求职 / 面试技巧”范围内，不写泛职场成长、穿搭、励志鸡汤或其他无关方向
- 8 条内容必须与上文列出的 8 个细分方向一一对应，不重复、不合并
- 标题需要接近当前仓库内 `topics.json` 的写法，偏小红书平台化表达，且是中文可直接发布标题
- audience 要尽量具体，例如“正在找工作的应届生”“准备跳槽的一线城市打工人”
- strategy 保持一句到两句，强调平台传播逻辑
- format 继续使用短横线分段风格，如 `求职技巧-自我介绍`
- priority 仅使用 `P0` / `P1`，以 `P0` 为主，必要时个别 `P1`
